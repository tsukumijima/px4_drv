# Linux 版の実機検証待ち一覧

この文書は、Linux ドライバへ入れた変更のうち、Windows 検証環境では確かめられず Linux 実機での確認が残っている項目をまとめたものです。  
確認が済んだ項目はこの一覧から外し、結果を日付付きの検証記録へ残してください。

Windows 版で実測により確定した不具合は、OS と API が違っても同じハードウェアを操作するため、Linux 版にも同じ条件が残っていることがあります。  
そうした横展開の修正は、根拠となった Windows 側の実測と対にして記録します。

## 検証環境の前提

Windows 検証環境には Linux カーネルのヘッダーがないため、`driver/` のビルドと動作確認は一切行えません。  
以下の項目はすべて、対象カーネルでのビルドと実機受信を Linux 側で実施する必要があります。

## 待機中の項目

### PXMLT 系のロック後待機

`driver/pxmlt_device.c` の `chrdev_config[i].options` へ `PTX_CHRDEV_WAIT_AFTER_LOCK_TC_T` を追加しました。  
PXMLT 系だけがこのフラグを持たず、ISDB2056 系、PX-M1UR、PX-S1UR、PX4 系はいずれも設定済みという非対称がありました。

根拠は WinUSB 版での実測です。  
PX-MLT5PE で ch8 と ch14 を往復すると、待機なしでは12周期65万パケットに対し同期エラー4件と transport error 14件が出ましたが、待機を入れると32周期176万パケットで両方とも0件になりました。  
CXD2856ER のロック判定はレジスタを1回読むだけで整定を待たないため、復調が安定する前の TS がそのまま流れることが原因です。  
Linux 版も同じ復調器を同じ判定方法で扱っており、待機の実装 (`driver/ptx_chrdev.c`) も WinUSB 版と同じ構造です。

確認すること。

- PX-MLT5PE または PX-MLT8PE でチャンネルを往復し、切り替え直後のドロップ、同期エラー、transport error が減ることを測る
- 同じ試験を PX4 系と ISDB2056 系でも実行し、この変更による退行がないことを確かめる
- 選局にかかる時間が実用上問題ない範囲に収まることを確かめる

### 既存の Linux 向け修正

次の修正は現行コードへ入っていますが、対象カーネルでのビルドと実機確認が残っています。

- `1e1e53a` USB ストリーム受信の入力検査と URB 回収
- `ed28d77` PX4 系の初期化時の基板電源停止
- `2d96544` PX4 複数デバイスの電源管理と参照寿命
- `2559c7b` ISDB2056 の初期化失敗時の電源処理
- `5cc2e7b` PX4 複数デバイス登録失敗時の参照寿命
- `5eb4771` PX4 複数デバイスの初期化時の基板電源停止 (GPIO2 の追加)
- `f734897` TS ストリーム受信長の検査

Issue #36 に関わる項目では、未使用時のランプ消灯と、受信開始後の正常な点灯を確かめてください。

## 横展開を検討したが Linux 側には該当しなかった項目

WinUSB 版で修正した内容のうち、Linux 版に同じ条件がないものを記録します。  
再調査の重複を避けるためのものであり、将来コードが変わった場合は再確認が必要です。

- 名前付きパイプの取り消し漏れ (読み書きと接続待ちの双方)、制御パイプとデータパイプの受信長検証、デバイス列挙の無限ループ、WinSCard API の ATR 長検証は、いずれも Windows 固有の API と DriverHost_PX4 の構成に閉じた問題です
- カードの T=1 処理と例外時の後始末は、Linux 側に内蔵カードリーダーの実装がまだ存在しないため対象外です
