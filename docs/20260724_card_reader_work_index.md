## この文書群の目的

この日付を持つ文書群は、内蔵カードリーダー対応の実装方法だけでなく、2026年7月24日時点で何を根拠に採用し、どこまで確認し、何を未確認として残したかを保存するものです。

リポジトリ外の読者も参照できる公開文書として記述します。  
対話相手を示す呼称は使わず、判断した人物は役割に応じて「メンテナ」、実装や検証を行った主体は「開発作業」または「Windows 検証環境」と記します。  
Markdown ソースは一文ごとに改行し、同じ段落内の各行末へ半角スペース2つを置いて、表示上も文単位で改行します。  

記録の基準となるブランチは `develop` です。

## 根拠の分類

文書中の主張は、次の種類を区別して読みます。  

- **現行コード確認**：基準コミットのソース、テスト、コミット履歴から直接確認した事項
- **自動試験**：模擬 I/O や API 試験を実際に実行して確認した事項
- **Windows 実機試験**：Windows 検証環境へ接続した PX-MLT5PE、DTV02A-1T1S-U (ISDB2056)、PX-W3U4 で確認した事項
- **外部実測**：フォーク作者や Issue 投稿者が、別の機種や環境で確認した事項
- **論理的判断**：コードと実測を組み合わせ、採否を決めた事項
- **未確認**：対象機材、Linux 環境、長期稼働時間、試験ログが不足している事項

外部実測は、同じ機種と条件を Windows 検証環境でも再現したことを意味しません。  
論理的判断は、コードレビューだけで長期稼働を証明したことを意味しません。  

## 2026年7月24日時点の作業境界

Windows 側では、B-CAS と ACAS の T=1 状態機械、UART フレーム上限、共有電源、WinSCard API、外付けリーダーとの共存、カードと TS の同時負荷まで、Windows 検証環境で実行できる範囲を確認しました。  
この範囲を Linux 実装の基準にします。  

Linux 側では、共通の `it930x_bcas_*()` に38400bps対応まで入っています。  
一方、Linux カーネルモジュールのビルド、既存の電源と参照寿命修正の実機確認、内蔵カードリーダーのカーネルデバイスと PC/SC IFD ハンドラーは残っています。  

Issue #38 の長期稼働再発確認は、現象を報告した利用者へ依頼する方針です。  
この確認待ちは Windows 実装の追加作業ではありませんが、Issue を完全解決した根拠にもなりません。  

PX-W3U4 の BS と CS は、Windows 検証環境に衛星波のアンテナを接続していないため試験していません。  
Linux 側と他環境で受信実績があるため、今回の内蔵カードリーダー実装を開始する前提からは除外しています。  

## 更新方法

この文書群の判断を後続作業で覆す場合は、古い文書を削除せず、新しい日付の判断記録から変更理由と新しい根拠を示してください。  
実機試験を追加した場合は、機種、カード、アンテナ、試験時間、D、E、S、APDU 失敗数を [`20260724_validation_record.md`](20260724_validation_record.md) の後継文書へ記録します。  

この日付の文書は、2026年7月24日時点のスナップショットとして固定します。  
現行仕様の説明だけを更新して過去の未確認事項を確認済みに書き換えると、当時の判断根拠を失うためです。
