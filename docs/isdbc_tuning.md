# ISDB-C と J.83 Annex B の選局の仕様

この文書は、PX-MLT 系 (PX-MLT5PE / PX-MLT8PE / DTV02A-5TS-P / DTV02A-4TS-P / PX-MLT5U) で、トランスモジュレーション方式の CATV (ISDB-C / ITU-T J.83 Annex C) とスカパー！プレミアムサービス光 (J.83 Annex B) を選局する仕組みを、受信ソフトウェアやチャンネル定義を作る開発者向けにまとめたものです。  
利用者向けの使い方は [README](../README.md#ケーブルテレビとスカパープレミアムサービス光の受信) にあり、実装の経緯と実機での確認結果は [ISDB-C 対応の記録](20261018_isdbc_validation.md) にあります。

## 周波数

ISDB-C の物理チャンネルは、recpt1 と同じ番号 (0〜112) で表します。  
地上波と異なり、中心周波数に 1/7MHz を加えません。

| 番号 | チャンネル | 中心周波数 |
|---|---|---|
| 0〜2 | VHF 1〜3ch | 93MHz から 6MHz 刻み |
| 3〜12 | CATV C13〜C22 | 111MHz から 6MHz 刻み (C22 は 167MHz) |
| 13〜21 | VHF 4〜12ch | 4〜7ch は 173MHz から 6MHz 刻み、8〜12ch は 195MHz から 6MHz 刻み |
| 22〜62 | CATV C23〜C63 | 225MHz から 6MHz 刻み |
| 63〜112 | UHF 13〜62ch | 473MHz から 6MHz 刻み |

C22 と VHF 4〜7ch は、ARIB STD-B21 付属10 の表10-2・表10-3 のとおり、6MHz 刻みの並びから 2MHz ずれています。  
C24〜C27 を 2MHz ずらした周波数 (233〜251MHz) を載せた資料もありますが、表10-4 では C23 から C63 までが 6MHz 刻みのため、規格どおり 6MHz 刻みにしています。

J.83 Annex B は、CATV のチャンネルとは別の 6.5MHz 刻みの並びを使います。  
公式の呼び名がないため、このリポジトリでは他の受信ソフトウェアの H 番号に合わせて H001〜H105 と呼び、H001 を 93.25MHz、H105 を 769.25MHz とします。  
番号は H105 まであるため、桁数がそろうよう3桁で書きます。  
Digital Devices のドライバーがスカパー！プレミアムサービス光に使う表は、この 6.5MHz 刻みに加えて、H028 を +4MHz ずらした 272.75MHz と、H044 を +2.2MHz ずらした 374.95MHz を持っています。  
radi-sh 氏の BonDriver_BDA も、H011〜H012 を +1MHz、H026〜H028 を +4MHz ずらした周波数でも作れるようにしていて、地域によってはこれらのずれた周波数で送られていると考えられます。  
番号から周波数を計算すると、このずれた周波数を表せないため、チャンネル定義と recisdb では J.83 Annex B を中心周波数で指定します。

## TSMF の TS の選び方

1つの搬送波に複数の TS を多重する TSMF では、搬送波から受信する TS を「TSMF のヘッダーで有効になっている TS を相対 TS 番号の順に並べ、0 から数えた番号」(TS0〜TS14) で指定します。  
BS の TS0・TS1 と同じ数え方で、チャンネル定義の名前と recisdb のチャンネル指定もこの番号を使います。  
相対 TS 番号は 0 から詰めて使われるとは限らず、イッツコムの回線でも 1 から始まる搬送波があるため、相対 TS 番号そのものではなく並びの中の位置で選びます。  
TSID で選ぶ方法は、ケーブルテレビ局ごとにチャンネル定義を作り分ける必要があるため採用しませんでした。

TS 番号の指定は、選局してから最初にその TS を見つけたヘッダーで相対 TS 番号に決まり、選局し直すまで同じ相対 TS 番号の TS を出力します。  
事業者が受信中に有効な TS の組を変えても別の TS へは切り替わらず、決まった TS がヘッダーで無効になれば何も出力しません。

ドライバーは ISDB-C の受信をすべて TSMF の分離処理へ通し、選局の後に届いた TS からヘッダーの有無を判断します。  
J.83 Annex B は TSMF を使わないため、ISDB-C とは別の放送方式として選局し、分離処理を通しません。

- ヘッダーがあれば、指定した番号の TS だけを出力します。その TS がヘッダーにない場合は選局に失敗します
- TS0 を指定して、ヘッダーのない搬送波だった場合は、搬送波の TS をそのまま出力します
- TS1 以降を指定して、ヘッダーのない搬送波だった場合は、選局に失敗します

ヘッダーは53パケットごとに届くため、8フレーム分 (424パケット) の間に1つも届かなければ、ヘッダーのない搬送波と判断します。  
受信の誤りでヘッダーを数回落としても、TSMF の搬送波をヘッダーのない搬送波と誤って判断しない長さです。  
ヘッダーのない搬送波と判断した後でもヘッダーが届けば、TSMF の搬送波として選び直します。  
一方、一度ヘッダーを受け取った後は、ヘッダーが途切れてもヘッダーのない搬送波とは判断せず、別の TS のパケットを出力しません。

選んだ TS は、フレームの52パケットがそろったことを次のヘッダーで確認してから出力します。  
次のヘッダーの位置に、受信の誤りで CRC が合わないヘッダー (PID 0x002f のパケット) が届いたときも、パケットの欠落ではないため、そろった前のフレームは出力します。  
直後のフレームは位置の基準となるヘッダーがないため出力せず、次の正しいヘッダーから選び直します。

選局し直した直後は、IT930x の転送1回分 (既定で816パケット) に前の搬送波の TS が残っていて、新しい搬送波のロックの後に届くことがあります。  
前の搬送波のヘッダーで判断すると、ヘッダーのない搬送波を TSMF と判断して何も出力しなくなるため、ロックしてから転送1回分のパケットは判断に使わずに捨てます。  
PX-MLT5PE で測った前の搬送波の残りは、最大で 710 パケットでした。  
残りは、TS の出力を止めた時点で途中まで埋まっていた転送が新しい搬送波の TS で満たされて届いたものと考えられ、測った値も転送1回分に収まっていました。  
IT930x のバッファーをまとめて捨てる PSB の purge は、ほかの受信機の TS も捨ててしまうため、選局し直しでは使っていません。

選んだ TS の stream_type が分割 TLV の場合は、TLV パケットを取り出して出力します。  
ただし、その TS が分割 TLV の PID 0x002d と null パケット以外のパケットを運んでいれば、MPEG-2 TS と判断し、選局し直すまでそのまま出力します。  
受信エラーで transport_error_indicator が立ったパケットは PID も壊れていることがあるため、この判断には使いません。  
stream_type の位置の読み方はイッツコムのヘッダーでしか確認できていないため、読み違えたときも MPEG-2 TS の出力が空にならないようにしています。  
4K 放送の TLV は TS のままでは受信ソフトウェアが扱えないため、[BonDriver_dantto4k](https://github.com/nekohkr/dantto4k) などの変換を前提にしています。  
TLV の出力は、この文書の作成時点で実機の 4K の搬送波では検証していません。

TSMF はヘッダーからの位置で TS を選ぶため、ISDB-C では IT930x の null パケットの除去を使わず、TS を選んだ後で null パケットを除きます。

## Windows のチャンネル定義

ISDB-C は `BonDriver_PX4-C.ChSet.txt` 、J.83 Annex B は `BonDriver_PX4-J83B.ChSet.txt` に、方式ごとに分けて書きます。  
`BonDriver_PX-MLT.ini` の `System` では、それぞれ `ISDB-C` と `J.83B` で有効にします。

`BonDriver_PX4-C.ChSet.txt` の各行は次の5列です。

| 列 | 内容 |
|---|---|
| 1 | チャンネル名 |
| 2 | チャンネル空間 ID |
| 3 | チャンネル ID |
| 4 | 物理チャンネル番号 (0〜112) |
| 5 | TSMF の TS 番号 (0〜14) |

`BonDriver_PX4-J83B.ChSet.txt` の各行は、TSMF の列のない次の4列です。

| 列 | 内容 |
|---|---|
| 1 | チャンネル名 |
| 2 | チャンネル空間 ID |
| 3 | チャンネル ID |
| 4 | 中心周波数 (kHz、90000〜770000) |

同梱の ISDB-C のファイルは、VHF 1ch から UHF 62ch までの全チャンネルを周波数の順に並べ、それぞれに `C52Ch/TS0`〜`C52Ch/TS3` のような TS0 から TS3 までの行を置いています。  
同梱の J.83 Annex B のファイルは、H001〜H105 の105波と、H011〜H012・H026〜H028・H044 のずれた周波数の6波を、周波数の順に並べています。  
ケーブルテレビ局ごとの違いはスキャンで吸収するため、利用者がこれらのファイルを編集する必要はありません。  
ISDB-C の TS1 以降の行は、TSMF を使わない搬送波では選局に失敗し、受信ソフトウェアのスキャンで除かれます。

## Linux の ioctl

TSMF を使わない ISDB-C は、既存の ioctl で選局できます。  
`PTX_SET_SYSTEM_MODE` で放送方式を `PTX_ISDB_C_SYSTEM` にしてから、`PTX_SET_CHANNEL` の `freq_no` に物理チャンネル番号 (0〜112) を、`slot` に周波数の補正値 (kHz) を指定します。  
この方法では、TSMF の搬送波は TS0 を受信します。

TSMF の TS1 以降と J.83 Annex B は、拡張 ioctl を次の順に呼び出して選局します。  
拡張 ioctl で選局できるのは ISDB-C と J.83 Annex B だけで、地デジと BS/CS は既存の ioctl で選局します。

1. `PTXT_SET_PARAMS` で、放送方式 (ISDB-C は `PTX_ISDB_C_SYSTEM` 、J.83 Annex B は `PTX_J83B_SYSTEM`)・中心周波数 (kHz)・追加パラメーターを渡す
2. `PTXT_TUNE` で選局する。ロックしない場合は `EAGAIN` 、指定した番号の TS がない場合は `ENODATA` で失敗する
3. `PTX_START_STREAMING` の後、`read()` で TS を読み出す

`struct ptxt_params` は、32 ビットと 64 ビットのプロセスで配置が変わらないよう、追加パラメーターの配列 (`struct ptxt_additional_param`) のアドレスを `__u64` の `prop` で渡し、`reserved` は `0` にします。

| 追加パラメーター | 値 |
|---|---|
| `PTXT_TSMF_STREAM_PARAM` | ISDB-C だけで指定でき、TSMF の TS 番号 (`0`〜`14`、省略時は `0`) |

`PTX_START_STREAMING` では、選局で決めたヘッダーの有無の判断を保ったまま、フレームの途中の状態だけを捨てます。  
TSMF で選んだ TS は毎秒数 KB のこともあるため、ISDB-C の `read()` は、200 ミリ秒たっても要求した量がそろわなければ、それまでに読めた分を返します。

受信中の C/N は `PTX_GET_CNR` で読み出せます。  
地デジや BS/CS と同じく復調器の生値 (C/N 推定用の `IREG_SNR_ESTIMATE`) を返すため、ISDB-C と J.83 Annex B では、Sony の `sony_demod_isdbc_monitor_SNR()` と同じ次の式で dB へ換算してください。

```
C/N (dB) = -9.50 × ln(max(生値, 126)) + 95.941 (生値が 0 のときは信号なし)
```

ISDB-C か J.83 Annex B を選局したデバイスファイルを閉じると、放送方式の指定は未指定へ戻ります。  
地デジと同じチャンネル番号を使うため、次に放送方式を指定せずに選局する受信ソフトウェアが ISDB-C を選局しないようにしています。
