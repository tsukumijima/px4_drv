# ISDB-C と J.83 Annex B の選局の仕様

この文書は、PX-MLT 系 (PX-MLT5PE / PX-MLT8PE / DTV02A-5TS-P / DTV02A-4TS-P / PX-MLT5U) で、トランスモジュレーション方式の CATV (ISDB-C / ITU-T J.83 Annex C) とスカパー！プレミアムサービス光 (J.83 Annex B) を選局する仕組みを、受信ソフトウェアやチャンネル定義を作る開発者向けにまとめたものです。  
利用者向けの使い方は [README](../README.md#ケーブルテレビとスカパープレミアムサービス光の受信) にあり、実装の経緯と実機での確認結果は [ISDB-C 対応の記録](20261018_isdbc_validation.md) にあります。

## 周波数

ISDB-C の物理チャンネルは、recpt1 と同じ番号 (0〜112) で表します。  
地上波と異なり、中心周波数に 1/7MHz を加えません。

| 番号 | チャンネル | 中心周波数 |
|---|---|---|
| 0〜2 | VHF 1〜3ch | 93MHz から 6MHz 刻み |
| 3〜12 | CATV C13〜C22 | 111MHz から 6MHz 刻み (C22 は 167MHz) |
| 13〜21 | VHF 4〜12ch | 4〜7ch は 173MHz から 6MHz 刻み、8〜12ch は 195MHz から 6MHz 刻み |
| 22〜62 | CATV C23〜C63 | 225MHz から 6MHz 刻み |
| 63〜112 | UHF 13〜62ch | 473MHz から 6MHz 刻み |

C22 と VHF 4〜7ch は、ARIB STD-B21 付属10 の表10-2・表10-3 のとおり、6MHz 刻みの並びから 2MHz ずれています。  
C24〜C27 を 2MHz ずらした周波数 (233〜251MHz) を載せた資料もありますが、表10-4 では C23 から C63 までが 6MHz 刻みのため、規格どおり 6MHz 刻みにしています。

J.83 Annex B は、CATV のチャンネルとは別の 6.5MHz 刻みの並びを使います。  
公式の呼び名がないため、このリポジトリでは他の受信ソフトウェアに合わせて H01〜H77 と呼び、H01 を 93.25MHz、H77 を 587.25MHz とします。  
radi-sh 氏の BonDriver_BDA は、H11〜H12 を +1MHz、H26〜H28 を +4MHz ずらした周波数でも作れるようにしていて、地域によってこの5波はずれた周波数で送られていると考えられます。  
番号から周波数を計算すると、このずれた周波数を表せないため、チャンネル定義と recisdb では J.83 Annex B を中心周波数で指定します。

## TSMF の TS の選び方

1つの搬送波に複数の TS を多重する TSMF では、搬送波から受信する TS を「TSMF のヘッダーで有効になっている TS を、相対 TS 番号の順に並べたときの何本目か」(1〜15) で指定します。  
相対 TS 番号は 0 から詰めて使われるとは限らず、イッツコムの回線でも 1 から始まる搬送波があるため、相対 TS 番号そのものではなく順番で選びます。  
TSID で選ぶ方法は、ケーブルテレビ局ごとにチャンネル定義を作り分ける必要があるため採用しませんでした。

ドライバーは ISDB-C の受信をすべて TSMF の分離処理へ通し、選局の後に届いた TS からヘッダーの有無を判断します。  
J.83 Annex B は TSMF を使わないため分離処理を通さず、TSMF の2本目以降の指定も受け付けません。

- ヘッダーがあれば、指定した何本目の TS だけを出力します。その TS がヘッダーにない場合は選局に失敗します
- 1本目を指定して、ヘッダーのない搬送波だった場合は、搬送波の TS をそのまま出力します
- 2本目以降を指定して、ヘッダーのない搬送波だった場合は、選局に失敗します

ヘッダーは53パケットごとに届くため、8フレーム分 (424パケット) の間に1つも届かなければ、ヘッダーのない搬送波と判断します。  
受信の誤りでヘッダーを数回落としても、TSMF の搬送波をヘッダーのない搬送波と誤って判断しない長さです。  
ヘッダーのない搬送波と判断した後でもヘッダーが届けば、TSMF の搬送波として選び直します。  
一方、一度ヘッダーを受け取った後は、ヘッダーが途切れてもヘッダーのない搬送波とは判断せず、別の TS のパケットを出力しません。

選局し直した直後は、IT930x の転送1回分 (既定で816パケット) に前の搬送波の TS が残っていて、新しい搬送波のロックの後に届くことがあります。  
前の搬送波のヘッダーで判断すると、ヘッダーのない搬送波を TSMF と判断して何も出力しなくなるため、ロックしてから転送1回分のパケットは判断に使わずに捨てます。  
PX-MLT5PE で測った前の搬送波の残りは、最大で 710 パケットでした。  
残りは、TS の出力を止めた時点で途中まで埋まっていた転送が新しい搬送波の TS で満たされて届いたものと考えられ、測った値も転送1回分に収まっていました。  
IT930x のバッファーをまとめて捨てる PSB の purge は、ほかの受信機の TS も捨ててしまうため、選局し直しでは使っていません。

選んだ TS の stream_type が分割 TLV の場合は、TLV パケットを取り出して出力します。  
4K 放送の TLV は TS のままでは受信ソフトウェアが扱えないため、[BonDriver_dantto4k](https://github.com/nekohkr/dantto4k) などの変換を前提にしています。  
TLV の出力は、この文書の作成時点で実機の 4K の搬送波では検証していません。

TSMF はヘッダーからの位置で TS を選ぶため、ISDB-C では IT930x の null パケットの除去を使わず、TS を選んだ後で null パケットを除きます。

## Windows のチャンネル定義

`BonDriver_PX4-C.ChSet.txt` の各行は次の5列です。

| 列 | 内容 |
|---|---|
| 1 | チャンネル名 |
| 2 | チャンネル空間 ID |
| 3 | チャンネル ID |
| 4 | ISDB-C は物理チャンネル番号 (0〜112)、J.83 Annex B は中心周波数 (kHz、90000〜770000) |
| 5 | TSMF の何本目 (1〜15)。J.83 Annex B は TSMF を使わないため `1` だけ |

同梱のファイルは、ISDB-C の空間に VHF 1ch から UHF 62ch までの全チャンネルを周波数の順に並べ、それぞれに1本目から4本目までの行を置いています。  
J.83 Annex B の空間には、H01〜H77 の77波と、H11〜H12・H26〜H28 のずれた周波数の5波を、周波数の順に並べています。  
ケーブルテレビ局ごとの違いはスキャンで吸収するため、利用者がこのファイルを編集する必要はありません。  
2本目以降の行は、TSMF を使わない搬送波では選局に失敗し、受信ソフトウェアのスキャンで除かれます。

## Linux の ioctl

TSMF を使わない ISDB-C は、既存の ioctl で選局できます。  
`PTX_SET_SYSTEM_MODE` で放送方式を `PTX_ISDB_C_SYSTEM` にしてから、`PTX_SET_CHANNEL` の `freq_no` に物理チャンネル番号 (0〜112) を、`slot` に周波数の補正値 (kHz) を指定します。  
この方法では、TSMF の搬送波は1本目を受信します。

TSMF の2本目以降と J.83 Annex B は、拡張 ioctl を次の順に呼び出して選局します。

1. `PTXT_SET_PARAMS` で、放送方式 (`PTX_ISDB_C_SYSTEM`)・中心周波数 (kHz)・追加パラメーターを渡す
2. `PTXT_TUNE` で選局する。ロックしない場合は `EAGAIN` 、指定した何本目の TS がない場合は `ENODATA` で失敗する
3. `PTX_START_STREAMING` の後、`read()` で TS を読み出す

| 追加パラメーター | 値 |
|---|---|
| `PTXT_SYMBOL_RATE_PARAM` | `5274` は ISDB-C (省略時)、`5600` は J.83 Annex B |
| `PTXT_TSMF_STREAM_PARAM` | TSMF の何本目 (`1`〜`15`、省略時は `1`) |

`PTX_START_STREAMING` では、選局で決めたヘッダーの有無の判断を保ったまま、フレームの途中の状態だけを捨てます。

受信中の C/N は `PTX_GET_CNR` で読み出せます。  
ISDB-C には PT 互換の値の定義がないため、地デジや BS/CS とは異なり、C/N (dB) を1000倍した値を返します。

ISDB-C を選局したデバイスファイルを閉じると、放送方式の指定は未指定へ戻ります。  
地デジと同じチャンネル番号を使うため、次に放送方式を指定せずに選局する受信ソフトウェアが ISDB-C を選局しないようにしています。
