# 2026年10月14日 Linux 版内蔵カードリーダーの実機確認の記録

この文書は、Linux 版の内蔵カードリーダー対応 (`feature/linux-card-reader` ブランチ) を実機で確かめた結果と、確かめられていない機種・条件をまとめたものです。  
構成と取り決めは [Linux 版内蔵カードリーダーの設計資料](../userland/ifd-px4/README.md) を参照してください。

## 検証環境

この記録の「WSL 検証環境」は、次の構成を指します。

- Windows 11 上の WSL2 (Ubuntu 24.04 、カーネル 6.18.54.1-microsoft-standard-WSL2)
- チューナーは Windows に USB 接続し、usbipd-win の USB/IP で WSL2 へ渡している
- pcsc-lite 2.0.3 (Ubuntu 24.04 のパッケージ) の pcscd を root で起動し、IFD ハンドラーはこのブランチからビルドして配置
- カードはいずれも内蔵スロットに挿した B-CAS で、ATR は `3b f0 12 00 ff 91 81 b1 7c 45 1f 03 99`
- アンテナは、PX-MLT5PE と DTV02A-1T1S-U には地上波と BS を、PX-W3U4 には地上波だけを接続

USB/IP と仮想マシンを経由するため、TS のドロップ・同期エラー・連続性エラーは、ネイティブ Linux の結果として評価していません。  
TS の計数は、受信が止まらずに続くことの確認として扱っています。

APDU の試験には、pcscd 経由でカードへ B-CAS の初期設定コマンド (`90 30 00 00 00`) を繰り返し送り、`90 00` が返った数と処理時間を数えるツールを使いました。  
基板電源の遷移は、各機種の `*_backend_set_power()` の dynamic debug をカーネルログへ出して確かめています。

## 確認できたこと

この節の表と続く段落は f5082d7 までの変更 (デバイスファイルが `/dev/px4cardN` だった版) での結果です。

| 機種 | カードリーダーの列挙と APDU | チューナーとの同時使用と基板電源 | その他 |
|---|---|---|---|
| PX-MLT5PE | 200回成功 (平均 92.4ms 、最大 97.6ms) | 両方の順序で確認 | 通信中の USB 切断と再接続 |
| PX-W3U4 | 100回成功 (平均 92.6ms 、最大 100.2ms) | 両方の順序で確認 | |
| DTV02A-1T1S-U | 100回成功 (平均 82.6ms 、最大 87.6ms) | 両方の順序で確認 | PX-M1UR を統合した後の版でも受信と APDU を確認 |

同時使用の試験では、カードを先に開いてチューナーを開き、カードを先に閉じる順序と、チューナーを先に開いて先に閉じる順序の両方を確かめました。  
どの機種でも、APDU は失敗せず、受信も最後まで続きました。  
基板電源は最初の利用者が開いたときに1回だけ入り、最後の利用者が閉じたときに1回だけ切れました。  
pcscd がカードの有無を問い合わせているだけの待機中は、電源は入りませんでした。

PX-MLT5PE では、APDU を連続で送っている最中に usbipd-win で USB を切断しました。  
アプリケーションには `SCARD_E_READER_UNAVAILABLE` が返り、`/dev/px4card0` は消え、カーネルログに警告や oops は出ませんでした。  
再接続すると `/dev/px4card0` が作り直され、APDU 50回がすべて成功しました。

PX-MLT5PE・PX-W3U4・DTV02A-1T1S-U の3台を同時に接続すると、3つのカードリーダーがそれぞれ別のリーダーとして列挙されました。

### DTV02A-1T1S-U の受信開始直後のエラーについて

DTV02A-1T1S-U で、カードへ APDU を送っている最中にチューナーを開いた1回の試験で、受信開始から 1.15〜1.22 秒の間に transport error indicator が25件、連続性エラーが4件出ました。  
カードの状態 (使っていない・電源だけ入れている・通信中) を変えて受信開始直後の8秒を4回ずつ、計12回繰り返したところ、すべて0件で再現しませんでした。  
カードの状態との関係は見られなかったため、カード対応による変化とは判断していませんが、原因は確かめられていません。

### /dev/px4card の下に作る形と deb での確認

デバイスファイルを `/dev/px4card/` の下に作る形にした版と、`build_ifd_deb.sh` で作った deb の IFD ハンドラーで、上と同じ3台を確かめ直しました。  
この時点のデバイスファイル名は USB のシリアル番号で、現在の ID の名前は後の「Windows 版と同じ ID の名前」の節で確かめています。

- 3台とも `/dev/px4card/` の下に作られ、権限は udev の規則どおり `root:video` の `0660` だった
- pcscd には `PLEX PX-MLT5PE Smart Card Reader (000042546005001) 00 00` のような名前で列挙され、3台へ同時に APDU を100回ずつ送り、すべて成功した
- PX-MLT5PE を APDU の送信中に切断すると、そのデバイスファイルだけが消え、再接続すると同じ名前で作り直された。再接続後の APDU 50回はすべて成功し、カーネルログに警告や oops は出なかった

### PX-M1UR

PX-M1UR を単独で接続し、カードを挿していない状態と、Mini B-CAS を挿した状態の両方を確かめました。

- カードなしでは、`pcsc_scan` がカードなし (Card removed) と表示し、アプリケーションからの接続には `SCARD_E_NO_SMARTCARD` (No smart card inserted) が返った
- カードありでは、ATR は `3b f0 12 00 ff 91 81 b1 7c 45 1f 03 99` で、単独の APDU 100回がすべて成功した (平均 87.0ms 、最大 93.6ms)
- チューナーとの同時使用は、カードを先に開いて地上波 27ch を受信する順序と、BS15_0 の受信を先に始めてカードを開く順序の両方で、APDU (200回と400回) がすべて成功し、受信の同期ずれ・TEI・連続性エラーは0件だった
- 基板電源は、どちらの順序でも最初の利用者が開いたときに1回だけ入り、最後の利用者が閉じたときに1回だけ切れた
- カードなしの状態でも、地上波 27ch と BS15_0 をそれぞれ20秒受信し、同期ずれ・TEI・連続性エラーはすべて0件だった

### 通信中のカードの抜去と再挿入

PX-M1UR で APDU を送り続けている最中に、Mini B-CAS を手で抜き、約5秒後に挿し直しました。

- 抜いた時点で送信中の APDU は失敗し、同じ接続のその後の APDU には `SCARD_W_REMOVED_CARD` (Card was removed) がすぐ (平均 9ms) 返った。応答を待ち続けて止まることはなかった
- `pcsc_scan` は、カードあり・カードなし・カードありの遷移を表示した
- 挿し直した後は、新しい接続で同じ ATR を取得し、APDU 50回がすべて成功した
- 接続を作り直しながら APDU を送り続ける形でも、2回の抜き差しのどちらの後も、挿し直した直後の接続から APDU が成功した
- カーネルログに警告や oops は出なかった

抜く前の接続には、挿し直した後も `SCARD_W_REMOVED_CARD` が返り続けます。  
これは PC/SC の取り決めどおりの動作で、アプリケーションは `SCardReconnect()` などで接続し直す必要があります。

### 受信とカード通信の同時実行

DKMS でインストールした同じ版で、全チューナーの受信と、3台のカードへの APDU の送信を同時に行いました。  
APDU は受信開始の3秒後から、3台へそれぞれ連続で送り続けています。

| 試験 | 受信したチューナー | 同期ずれ・TEI | 連続性エラー | APDU |
|---|---|---|---|---|
| 地上波 27ch 、120秒 | PX-MLT5PE の5基、PX-W3U4 の地上波2基、DTV02A-1T1S-U | すべて0件 | PX-MLT5PE のチューナー3で1件 | 3台とも896回成功 |
| BS15_0 、60秒 | PX-MLT5PE の5基、DTV02A-1T1S-U | すべて0件 | PX-MLT5PE のチューナー0・3・4で各1件 | 3台とも416回成功 |

連続性エラーは、いずれも受信開始から 1.8〜2.2 秒の時点に PID 256 で1件ずつ出たもので、APDU を送り始める前でした。  
カード対応の前の版でも、受信開始の約 1.7 秒後に同じ PID で1件出ることがあり、同じ傾向と見ています。  
最大読み出し間隔は、PX-MLT5PE のチューナー0の地上波の 0.234 秒を除いて 0.07 秒以下でした。

### Docker のコンテナで pcscd を動かした場合

ホストの pcscd を止め、Ubuntu 24.04 のコンテナへ pcscd と deb の IFD ハンドラーを入れ、`/dev/px4card` と `/run/udev` を渡して確かめました。  
コンテナのネットワークだけを変えて、PX-MLT5PE の切断と再接続を比べています。

| ネットワーク | 起動時の列挙と APDU | 切断と再接続の後 |
|---|---|---|
| 既定 (bridge) | 3台を列挙し、APDU 30回成功 | 切断後も一覧に残り、再接続後も `SCARD_E_READER_UNAVAILABLE` のまま |
| host | 3台を列挙 | 切断で一覧から消え、再接続後の APDU 20回成功 |

pcscd の udev の通知はネットワーク名前空間ごとに届くため、抜き差しへ追従するには host ネットワークが必要です。  
また、Ubuntu の pcscd はコンテナ内で polkit に接続できず、`--disable-polkit` を付けるまですべてのクライアントを拒否しました。

3台を同時に外すと、カーネル (devtmpfs) が空になった `/dev/px4card` を削除しました。  
この状態では、コンテナに渡したディレクトリが削除済みのものを指し続け、再接続後のデバイスファイルがコンテナから見えません。  
`/dev/px4card` を systemd-tmpfiles で先に作る変更の後は、全台を外してもディレクトリが残りました。  
host ネットワークのコンテナを動かしたまま全台を外してつなぎ直すと、3台とも APDU 20回が成功しています。

### Windows 版と同じ ID の名前

デバイスファイル名を Windows 版のリーダー名の ID にした版を DKMS でインストールし、3台を同時に接続して確かめました。  
ID は、同じ機器の Windows 版のリーダー名に表示された値と一致しました (PX-M1UR は、TVTest の設定画面で見えた先頭4桁の `8E5C` までを照合)。

| 機種 | USB のシリアル番号 | デバイスファイル | Windows 版のリーダー名の ID |
|---|---|---|---|
| PX-M1UR | `000000000000001` | `/dev/px4card/8E5C59AEFF108DEA` | `8E5C59AEFF108DEA` |
| PX-W3U4 | `000001711009061` | `/dev/px4card/CD65353E4231AA77` | `CD65353E4231AA77` |
| PX-MLT5PE | `000042546005001` | `/dev/px4card/E0044EBBED627D79` | `E0044EBBED627D79` |

3台とも pcscd に列挙され、APDU 10回ずつがすべて成功しました。  
PX-M1UR と DTV02A-1T1S-U はどちらもシリアル番号が `000000000000001` ですが、PID と GUID が異なるため、ID は別の値になります。  
同じ機種でシリアル番号も同じ機器を複数台つないだ場合は ID も同じになり、2台目以降のデバイスファイル名には接続した順に `-1` などが付きます。  
手元に同じ機種が1台ずつしかないため、この場合と、シリアル番号を持たない機器の `usb-<USB の接続位置>` の名前は確かめられていません。

## 確かめられていないこと

- 手元に実機がない機種
  - PX4 系: PX-Q3U4・PX-Q3PE4・PX-Q3PE5 (2基連動の電源管理を含む)、PX-W3PE4・PX-W3PE5
  - PXMLT 系: PX-MLT5U・PX-MLT8PE・DTV02A-5TS-P・DTV02A-4TS-P
  - ISDB2056 系: ISDB2056N
  - ISDBT2071 系: PX-S1UR・DTV03A-1TU
- PX-M1UR 以外の機種での、通信中のカードの抜去と再挿入
- ACAS カード
- CS の受信と PX-W3U4 の衛星側のチューナー (同軸ケーブルを接続していない)、長時間の録画、ネイティブ Linux での TS の品質
- 外付けのカードリーダーとの共存

## 外部の報告

PR #43 の作者は、ネイティブ Linux (Ubuntu 24.04 、Linux 6.8) の DTV02A-5TS-P と B-CAS で、5系統の受信中に APDU を60秒送り続けて失敗0だったこと、Mirakurun で地上波と BS を同時に復号できたことを報告しています。  
この試験は、このブランチで手直しする前の版 (USB 制御転送ごとの期限を持つ版) で行われたものです。
