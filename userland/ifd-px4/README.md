# Linux 内蔵カードリーダー用 IFD ハンドラー

この実装は、DTV02A-5TS-P と PX-MLT5PE の内蔵カードリーダーを pcsc-lite へ接続するための初期実装です。
DTV02A-5TS-P の短時間の実機試験では、カード通信、5チューナーと APDU の同時動作、地上波・BS の復号を確認しています。
受信開始付近の TEI（transport error indicator）と復号後のスクランブル残りが出た試行もあるため、確認範囲と未解決条件は末尾の実機確認記録を参照してください。
対応機種は上記の2機種に限られ、カーネル側では `PXMLT5PE_MODEL` で判定しています。

## 構成

```text
アプリケーション → libpcsclite → pcscd → libifd-px4.so
                                         ↓
                                   /dev/px4cardN
                                         ↓
                          px4_drv → IT930x UART → カード
```

`pcscd` 本体のパッチは不要です。共有ライブラリと USB 検出用 `Info.plist` を、pcsc-lite の標準 IFD bundle として配置する構成です。
外付け CCID リーダーは、従来の `libccid` から利用できます。どちらのリーダーを使うかはアプリケーション側の選択に従います。

T=1 の状態機械と試験は、それぞれ [`smart_card.cpp`](../../winusb/src/DriverHost_PX4/smart_card.cpp) と [`smart_card_state_test.cpp`](../../winusb/tests/smart_card_state_test.cpp) を共用しています。
Windows 用のディレクトリにあるものの、Linux のビルドでは Windows API や WinSCard 互換 DLL への依存はありません。
通信速度は ATR が示す条件に従い、9600 / 19200 / 38400 bps と T=1 を扱います。任意の PPS 交渉や T=0 通信は対象外です。

カーネルが担う範囲は、機器寿命、単一 UART の排他、共有電源、カード検出、リセット、UART 送受信です。
カードの物理スロット1つにつき `/dev/px4cardN` を1つ作成し、複数アプリケーションからの共有を pcscd に集約しています。

## ビルドと配置

Debian / Ubuntu での IFD ビルドには C++17 コンパイラー、make、pkg-config、`libpcsclite-dev` が必要です。カーネルモジュールのビルドには対象カーネルのヘッダーと C コンパイラー、`driver` の自動試験には Python 3 も必要です。
実行先と同じディストリビューションでビルドすると、glibc / libstdc++ の必要な版を揃えられます。

リポジトリのルートから実行する例です。

```sh
make -C driver
make -C driver check
make -C userland/ifd-px4
make -C userland/ifd-px4 check
```

IFD のインストール先は `pkg-config --variable=usbdropdir libpcsclite` から取得できます。
配布用の一時ディレクトリへ配置する例です。

```sh
stage=$(mktemp -d)
make -C userland/ifd-px4 install DESTDIR="$stage"
```

配置されるファイルは次の2つです。

```text
<usbdropdir>/ifd-px4.bundle/Contents/Info.plist
<usbdropdir>/ifd-px4.bundle/Contents/Linux/libifd-px4.so
```

カーネルモジュールとカード用 udev 規則（[`etc/99-px4video.rules`](../../etc/99-px4video.rules)）の配置は、[Linux の導入手順](../../README.md#インストール-linux)を参照してください。内蔵カード対応は配布版 `v0.6.1` に含まれないため、このソースツリーからのビルドが必要です。
IFD bundle は DKMS パッケージに含まれないため、別途配置が必要です。

モジュールの入れ替えには受信デバイスの解放が必要です。録画・視聴・番組情報取得が停止できる保守時間に、旧モジュールと旧 IFD の復元方法を用意して反映してください。
`driver/Makefile` の `install` はモジュールの解除・再ロードも含むため、受信中の環境で実行しないでください。

### Docker で pcscd を動かしている場合

カーネルモジュールと udev 規則はホスト側、IFD bundle は pcscd が動くコンテナ側へ配置する必要があります。
コンテナには既存のチューナーデバイスに加えて、カードデバイスへのアクセスを渡します。

```yaml
devices:
  - /dev/px4card0:/dev/px4card0
```

これは追加する設定の抜粋です。番号は対象機器の sysfs 親情報と照合してください。
USB の再接続で minor 番号やカードデバイス名が変わる場合は、Docker のデバイス割り当ても見直す必要があります。
コンテナ内の USB 自動検出には、親 USB 機器と `/sys/class/misc/px4cardN/device` が同じ機器として参照できる sysfs の可視性が必要です。

### リーダーの検出と権限

USB 自動検出は libudev を有効にした pcsc-lite を対象とします。
IFD に渡された USB の bus / device 番号を、カードデバイスの sysfs 親へ照合するため、同型機を複数台接続しても最初に見つかったリーダーへ誤接続することを避けられます。
USB の通知とドライバ初期化の順序差に備え、デバイスの出現を最大3秒待機します。

固定設定が必要な環境では、`reader.conf.d` へ次のような設定を配置できます。
`LIBPATH` は実際の配置先へ合わせてください。USB bundle と固定設定を同じリーダーへ重複適用すると、排他的 open が衝突します。

```text
FRIENDLYNAME "DTV02A-5TS-P internal reader"
DEVICENAME /dev/px4card0
LIBPATH /usr/lib/pcsc/drivers/ifd-px4.bundle/Contents/Linux/libifd-px4.so
CHANNELID 0
```

udev 規則はカードデバイスを `root:video`、`0660` とし、`ID_PATH` が得られる場合は `/dev/px4card/by-path/` に接続位置からのリンクを作成します。
pcscd を非 root で起動する環境では、そのサービスの利用者にカードデバイスを開く権限が必要です。
固定設定のリーダーを USB 切断後に再登録する方法は pcsc-lite の設定再読み込み方式に依存するため、ホットプラグには USB bundle を優先してください。

## カーネル ABI

定義は [`include/px4_card_ioctl.h`](../../include/px4_card_ioctl.h) にあります。
他フォークの同名デバイスとは ioctl の互換性がありません。IFD は `PX4_CARD_GET_INFO` で ABI と転送上限を確認してから利用を開始します。

`open(O_RDWR)` は UART の所有権だけを確保し、カードへの電源投入・リセットは要求しません。
二重 open は `EBUSY` です。最後の fd を閉じる処理で、そのセッションが持つカードの電源参照も解放されます。

| 操作 | 内容 |
|---|---|
| `GET_INFO` | ABI 版1、UART 転送上限255バイト |
| `POWER` | `value=1` で共有電源参照取得と UART 初期化、`0` でカード停止と参照解放 |
| `DETECT` | カード挿入状態を `value` に返却。カード初期化は不要 |
| `RESET` | GPIO リセット、UART RX 初期化、9600 bps への復帰 |
| `SET_BAUDRATE` | `value` に 9600 / 19200 / 38400 を指定 |
| `RX_READY` | 完成応答の受信可能状態を `value` に返却 |
| `READ` | `length` に受信容量1〜255を指定し、実際の長さとデータを返却 |
| `WRITE` | `length` の1〜255バイトを1つの UART フレームとして送信 |

構造体はゼロ初期化が必要です。未使用の `value`・`length` と `reserved` は0を指定します。
機器操作の `deadline_ns` は `CLOCK_MONOTONIC` のナノ秒単位の絶対期限です。
カード操作を実行する task は、新しい USB 制御コマンドの送信前に期限を確認します。
送信済みコマンドを途中で打ち切ると後続の選局が古い応答を読むため、開始した TX と RX にはそれぞれ USB 制御転送の `ctrl_timeout` を使って応答を回収し、期限を越えていた場合は `ETIMEDOUT` を返す構成です。
この回収によって、要求期限の後にも最大で TX と RX 各1回分の USB 待機が加わります。USB 自体の切断・転送エラーは元のエラーを返すため、応答回収の成功を保証するものではありません。
`ctrl_timeout=0` の場合もカード要求の各転送は既定値の3秒で区切ります。並行する選局の設定値はそのままです。
すでに進行中の選局や共通制御ロックの待機、OS のスケジューリングまで含めた厳密な実時間上限を保証する API ではありません。
無期限の共有 USB 制御待機を避けるため、カード併用時には有限の `ctrl_timeout` を使用してください。

チューナー未使用時のカード電源投入が失敗した場合は、投入途中の GPIO も停止側へ戻す必要があります。
失敗した要求の期限で後始末まで拒否されることを避けるため、電源の後始末には `close` と同じ独立した3秒の期限を設定します。ここでも開始済みの制御コマンドには上記の応答回収待ちが加わります。
呼び出し元に返る値は元の投入エラーであり、受信機が利用中の共有電源は回収対象外です。

`poll()` は USB 切断で `POLLERR | POLLHUP` を返します。カード挿抜や UART 受信の通知はカーネル側の常時ポーリングを設けず、ユーザー空間の状態照会・期限付き待機で扱います。
ATR、T=1 連番、再送、WTX、APDU 分割は IFD 側の責務です。

USB 切断後の操作は `ENODEV`、電源停止中の通信は `EHOSTDOWN`、期限切れは `ETIMEDOUT`、形式不正は `EBADMSG` などとして返ります。
古い fd はカード用管理オブジェクトだけを保持し、切断された USB 機器の解放を待たせる参照を持ちません。

共有電源が受信機で利用されている間の `POWER(0)` は、カードのリセット線を保持してセッションを停止します。
カードだけの独立した電源断を意味する操作ではありません。最後のチューナー利用とカード利用の両方が終わった時点で基板電源を停止する構成です。

## 自動試験

`make -C driver check` は Python 3 と C コンパイラーを使い、現行ソースから抽出した USB 制御・電源関数を、模擬 USB 応答キュー・GPIO・時計へ接続します。
送信前・送信中・応答待ち中の期限切れ、後続制御の応答整合性、USB エラーの維持、電源投入途中の後始末、受信機との電源共有が試験対象です。
試験は実機を開かず、カーネルのロック競合・抜去時の寿命・TS 受信結果は別途確認が必要です。

`make -C userland/ifd-px4 check` は共用のカード状態遷移試験と、IFD API から Linux アダプターまで通す試験を実行します。
後者ではシステムコールだけを模擬し、未挿入、電源操作、T=1、応答バッファ、タイムアウト時の状態破棄、抜去、異なるリーダー間の分離、ABI 不一致を確認できます。

実際の pcscd と libpcsclite を使う統合試験は、専用 Docker コンテナ向けです。
IFD のビルド依存と `pcscd` を用意し、USB デバイスとホストの PC/SC ソケットを渡さず、pcscd がまだ起動していないコンテナを使ってください。
試験用デバイスファイルを作成するため、コンテナ内の root で、リポジトリのルートから次を実行します。

```sh
cd userland/ifd-px4
make integration-build
PX4_ISOLATED_TEST=1 sh tests/run-pcsc-integration.sh
```

実運用へ配置するファイルは `libifd-px4.so` です。`libifd-px4-test.so` は模擬カードを使う統合試験専用です。

## 実機試験

変更前のモジュールと外付けリーダーによる受信結果を基準に、同じチャンネル構成で比較してください。
対象機種、カーネル版、カード配置、地上波・BS・CS のアンテナ接続、試験時間の記録が必要です。

1. カード単独での列挙、未挿入・挿入、ATR、APDU 通信。
2. チューナーだけの受信、およびカード通信と最大5チューナーの同時受信。
3. カードを先に閉じる場合、最後のチューナーを先に閉じる場合、最後の利用者を閉じる場合の電源。
4. 通信中のカード抜去・再挿入、USB 切断・再接続、古い fd を保持した状態での新しいデバイスの利用。
5. 外付けリーダーとの共存、複数クライアントの共有・排他、pcscd 終了時の解放。
6. チャンネル切り替えと長時間受信。

計測項目は同期エラー、TEI、continuity counter エラー、空受信時間、復号後のスクランブル残り、APDU 失敗数、最大処理時間です。

### DTV02A-5TS-P の実機確認記録 (2026-10-12)

環境は Ubuntu 24.04、x86_64、Linux 6.8.0-146-generic、DTV02A-5TS-P 1台です。
内蔵リーダーの試験では、内蔵スロットに B-CAS を挿入し、外付けリーダーを外して、地上波と BS/CS のアンテナを接続した状態で、コンテナ内の pcsc-lite 1.9.9 とこの IFD を使用しました。
復号器は arib-b25-stream-test 0.2.9、受信は `recpt1 --device /dev/pxmlt5videoN <channel> <seconds> -` です。

- USB 自動列挙、ATR、T=1、共有接続、排他接続の拒否、トランザクション、リセット、電源停止後の再接続を確認。
- カード単独の初期設定 APDU (`90 30 00 00 00`) は10秒で56回成功、失敗0、最大81.456 ms。
- 地上波14ch・15ch、BS01_0・BS09_0、CS2を各45秒指定で並行受信。5系統とも同期エラー、TEI、連続性エラー、形式不正は0。読み出し間隔の最大値は90.325 msで、これはアプリケーション側の観測値です。
- 上記の選局前から全チューナー終了後まで60秒間 APDU を送り、327回成功、失敗0、最大1225.766 ms。
- 地上波15chの45秒と BS09_0の30秒では、内蔵カードによる復号後の同期エラー、TEI、連続性エラー、スクランブル残りは0。
- 地上波15chを40秒受信し、受信中にカードを10秒利用して閉じる試験を2回実施。1回はTEIが2個あり、発生時刻は未記録です。もう1回は同期エラー、TEI、連続性エラー、形式不正が0でした。APDU は両試行とも56回成功、失敗0。
- pcscd が UART を所有中の生デバイス二重 open は `EBUSY`。pcscd 終了後に別の pcscd から再接続できることも確認。

地上波14chの別の45秒復号試行では、復号前後でTEIが4個、復号後のスクランブル残りが702個ありました。
TEI は保存した復号前 TS の先頭234パケット以内に存在しましたが、スクランブル残りとの因果関係や、内蔵カード対応を加える前のモジュールとの違いは未確認です。
同じカード対応モジュールで外付け ACS ACR39U を使った地上波14chの30秒復号試行でも、復号後の TEI が6個、スクランブル残りが3個ありました。内蔵カード通信との関係は未確認です。

長時間録画、通信中のカード挿抜、USB 切断と古い fd の寿命、複数台・他機種、および Windows 版 x86/x64 のビルドは未確認です。
